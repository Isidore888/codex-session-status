# codex-session-status

Windows 下的 Codex 桌面客户端状态栏，在原生输入框底部显示六项只读数据：

`累计Token 1亿5234.5万  缓存命中率 96.8%  5小时剩余 82%  重置时间 03:57  执行模式 Work  任务耗时 00:50`

不修改客户端安装文件、登录配置或原图标。日常后台是 Windows 计划任务，使用项目内启动器和守护脚本；不是客户端内置功能。

## 显示内容

- 累计Token：当前会话 UUID 的累计快照，避免重复累加恢复记录。亿用整数，万最多一位小数，按千取整并进位、去掉末尾零。
- 缓存命中率：累计缓存输入 Token / 累计输入 Token。
- 5小时剩余、重置时间：客户端返回的 codex 300 分钟额度窗口；时间显示本地时分。
- 执行模式：当前 UUID 保存的 `originator`，精确对应 `Codex Desktop` / `codex_work_desktop`。不随左上角界面切换；不是对完整工具配置永远不变的承诺。
- 任务耗时：该 UUID 最新根任务的运行时间，完成或中止后固定，下个根任务重新计时；忽略子任务。

字体跟随客户端，排版紧凑。没有悬停提示或“未更新”标记；读取失败保留旧值并淡显，没有可靠数据显示 `—`。受支持的活动草稿或缺少本地记录的 UUID 可显示缺失／未知值；隐藏页缺少明确 UUID 时不准备状态行，普通 ChatGPT 页面及不支持的布局不注入。

## 刷新规则

| 内容 | 规则 |
| --- | --- |
| 守护检查 | 有客户端约每2秒检查；确认无客户端后约10秒。等待阶段每250毫秒检查停止标记。 |
| 会话与用量 | 约每2秒增量读取 UUID 元数据和日志完整行；UUID变化可提前唤醒下一轮。没有新累计快照时数字保持不变。 |
| 会话文件索引 | 常规15秒更新；遇到新 UUID 提前查找。 |
| 额度 | 成功后60秒安排下一次查询；失败按约2、5、10、15、30秒重试，随后维持30秒，成功后恢复60秒。 |
| 任务耗时 | 运行中按当前时间与开始时间计算到整秒；完成后固定，读取失败冻结最后可靠时长。 |
| 绘制 | 仅改变化的文字和状态；同已验证输入框的短暂编辑框缺口保留原行，隐藏原生页保留自己的行，未知页不借用别页 UUID。 |
| 临时不支持的布局 | 暂停当页更新，保留连接，合法布局恢复后自动补回；端点持续消失约30秒后结束监视器。 |

“接口耗时”指额度查询从发出到收到客户端返回的等待时间。因此刷新周期还受查询、读取及绘制影响，不承诺严格整分钟。重置时刻仍按接口时间戳显示，不因查询耗时向后推。

## 环境与首次配置

需要 Windows、受支持的 Microsoft Store Codex 桌面客户端、已有 Node.js 22+ 和 PowerShell 7。GUI 启动器使用 Windows 已有 .NET 编译器构建。项目没有 npm 第三方依赖，无需 `npm install`。

既有本机验收使用客户端 `26.1007.2314.0`。客户端布局、CDP 和本机额度接口属于版本敏感实现，不保证其他版本直接兼容。

**此仓库提供源码，不是下载后双击即可使用的通用安装包。** `runtime/` 不上传：它包含本机路径、已编译启动器、源代码审查记录和实机验收。新的电脑需要自己的真实审查及验收，不能复制其他电脑的通过记录或绕过门禁。

在项目目录中，用已有运行环境进行本机路径探测：

```powershell
.\配置桌面入口.ps1 -ProjectOnly
```

这只写入项目内 `runtime/environment.json`，不创建或修改桌面快捷方式。早期桌面入口脚本保留作参考，不建议执行不带 `-ProjectOnly` 的配置命令。

后续依据 [AGENTS.md](AGENTS.md)、`scripts/source-gates.ps1` 和管理脚本完成当前源码的独立审查、启动器构建及实机门禁，再安装后台任务。`Install` / `Start` 要求当前源码审查记录；`EnableLogon` 另要求启动、六项数值、计时、切换及布局等真实验收。仓库不包含伪造的默认通过记录。

## 已配置环境的日常运行与退出

登录 Windows 后后台自动运行。正常使用原图标、快捷方式或原客户端 EXE，无需每次双击项目脚本。

在本项目目录的 PowerShell 终端中执行：

```powershell
# 查看后台、客户端连接及登录自启动状态
.\管理状态栏.ps1 -Action Health

# 恢复已安装后台
.\管理状态栏.ps1 -Action Start

# 停止本工具后台及状态栏，客户端保持打开
.\管理状态栏.ps1 -Action Stop
```

`Stop` 不取消登录触发器，下次登录仍会启动。关闭客户端窗口可能只是隐藏；要结束客户端本身，使用它自己的“退出”。客户端退出后监视器结束，守护继续等待客户端。

已有 CDP 连接时可以直接加载或补回状态栏，无需重启客户端。没有调试端口的既有进程不能无损补加启动参数：守护启动时对已有进程仅观察；首次配置可能需要用户自行正常退出、重开。已配置守护发现新的无端口客户端时，按既有授权和进程归属、Restart Manager 影响范围校验，可正常退出并重开一次；不强制结束、不循环重开。这是调试连接的启动要求，普通数值刷新不需要重开。

`启动状态栏.cmd` 是早期手动启动入口，直接连接已有端口，或在没有客户端时带参数启动。它与登录守护的职责不同，不是日常每次必点的操作。

若本次终端限制执行脚本，可使用进程级策略：

```powershell
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\管理状态栏.ps1 -Action Health
```

将末尾操作换成所需项；不改变系统或用户执行策略。

## 自启动与卸载

以下命令只有在用户希望关闭、恢复或卸载时执行：

```powershell
# 关闭后台并取消登录自启动
.\管理状态栏.ps1 -Action Stop
.\管理状态栏.ps1 -Action DisableLogon

# 已通过当前源码及客户端验收时，重新启用自启动
.\管理状态栏.ps1 -Action EnableLogon
.\管理状态栏.ps1 -Action Start

# 停止并删除归属核验通过的唯一后台任务，保留源码及证据
.\管理状态栏.ps1 -Action Uninstall
```

任务名按项目路径生成，管理脚本先验证用户、任务动作、路径及进程归属。不要直接移动正在使用的项目；迁移前卸载原任务，再按新路径配置、审查和验收。

```powershell
node scripts/check.mjs
node --test tests/unit.test.mjs tests/startup-capabilities.test.mjs tests/plugin.test.mjs
```

Windows、启动及隔离浏览器测试矩阵见 [AGENTS.md](AGENTS.md)。生命周期夹具会用项目的控制管道和运行状态，运行前必须停止真实后台，不能与原生监视器并行。单元及隔离页面通过不代表实机通过；实机核对用只读数值、时间及布局元数据，不轮询客户端截图。

本机 v25 记录包含11组规定检查、28个 Node 测试、独立源码审查、隔离布局恢复及真实六项严格核对。真实 Windows 登录自启动在此前不变执行路径下验证通过。这些是既有本机历史证据，不证明新电脑或新客户端版本已经验收。真实未知布局故障注入、新一轮登录及CPU降幅专项测量未执行，也不作为新计划。

## 目录、数据与边界

- `src/`：会话元数据、额度读取、CDP、渲染和任务计时。
- `scripts/`：守护、管理、启动器构建、源代码门禁及验证工具。
- `tests/`：单元、Windows和隔离页面回归。
- `plugin/`：已撤回的早期插件试验与部分测试仍引用的共享模块，不自动安装或重新启用。
- `runtime/`：本机环境、启动器、日志、临时浏览器profile、验证及恢复资料，不提交。
- `handoffs/`、规划和进度文件：本机维护历史，不提交。

只读取 UUID 绑定的数字、身份和时间元数据；不保存聊天正文、凭据或完整接口响应。经过认证的桌面 RPC 仅允许 `account/rateLimits/read`。客户端自己的会话存储由客户端管理，本项目只读；Windows 计划任务由系统保存于项目外。已有 Node、PowerShell、浏览器可能自行产生工具缓存，不承诺项目外零写入。

后台日志已有约512KiB阈值清空策略，自动客户端历史最多保留8条。人工诊断和恢复证据另行保留，日常运行不会自动扩增它们。发布源码不清理用户证据、不改变后台行为。
